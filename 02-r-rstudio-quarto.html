2  Introdução ao R, ao RStudio, à edição de texto, à internet e às planilhas eletrônicas

Objetivo da aula prática

Neste capítulo, você não precisa memorizar todos os comandos. O objetivo é compreender como organizar um trabalho reprodutível, executar instruções no R, importar dados, reconhecer a estrutura de uma planilha e produzir um pequeno documento em Quarto.

2.1 Objetivos de aprendizagem

Ao final deste capítulo, espera-se que o estudante seja capaz de:

  • distinguir R e RStudio;
  • reconhecer as principais áreas da interface do RStudio;
  • criar e salvar um projeto;
  • diferenciar console, script, objeto e função;
  • instalar e carregar pacotes;
  • obter ajuda sobre funções;
  • criar vetores e uma tabela de dados simples;
  • importar arquivos CSV e XLSX;
  • identificar linhas, colunas, casos e variáveis;
  • reconhecer princípios de organização de planilhas;
  • pesquisar dados e documentação na internet com critérios de confiabilidade;
  • utilizar a sintaxe básica de Markdown e os blocos de código do Quarto;
  • produzir e salvar um relatório simples e reprodutível.

2.2 R e RStudio não são a mesma coisa

  • R é uma linguagem e um ambiente para computação estatística, manipulação de dados e produção de gráficos.
  • RStudio é um ambiente integrado de desenvolvimento que facilita a escrita de códigos, a organização de arquivos, a visualização de resultados e a produção de documentos.

Uma analogia útil:

  • o R é o motor;
  • o RStudio é o painel de controle e o espaço de trabalho.

2.3 Organização da pasta da disciplina

Antes de programar, organize o trabalho. Uma estrutura simples é:

AED/
├── dados/
├── figuras/
├── relatorios/
├── scripts/
└── capitulos_1_2.qmd
  • dados/: arquivos originais e bancos preparados;
  • figuras/: imagens exportadas;
  • relatorios/: versões finais dos documentos;
  • scripts/: códigos auxiliares;
  • arquivo .qmd: texto, código e resultados da análise.
Evite trabalhar com arquivos espalhados

Projetos com arquivos em Downloads, Área de Trabalho, pendrive e serviços de nuvem ao mesmo tempo tendem a produzir caminhos quebrados, duplicidades e versões conflitantes.

2.4 Criando um projeto no RStudio

No RStudio:

  1. acesse File > New Project;
  2. escolha New Directory;
  3. selecione New Project;
  4. escolha um nome, por exemplo AED;
  5. selecione a pasta onde o projeto será criado;
  6. clique em Create Project.

O projeto ajuda a manter caminhos relativos. Em vez de escrever um caminho específico de um computador, como:

C:/Users/Nome/Documents/AED/dados/estudantes.csv

podemos usar:

dados/estudantes.csv

Isso facilita a transferência do projeto entre computadores.

2.5 Principais áreas do RStudio

Área Função principal

Use o console para testes rápidos. Registre no script ou no arquivo Quarto todo comando necessário para reproduzir a análise.

2.6 Seu primeiro contato com o R

Uma expressão pode ser executada diretamente.

Código 
2 + 3
[1] 5

O operador <- é utilizado para atribuir um valor a um objeto.

Código 
numero_de_estudantes <- 35
numero_de_estudantes
[1] 35

O objeto fica disponível na sessão.

Código 
numero_de_estudantes * 2
[1] 70

2.6.1 Nomes de objetos

Prefira nomes informativos:

Código 
media_da_turma <- 7.4
taxa_de_aprovacao <- 0.82

Evite nomes pouco explicativos:

Código 
# Evite quando o significado não estiver claro
x <- 7.4
y <- 0.82

Uma convenção útil é snake_case, com palavras separadas por sublinhados.

2.7 Funções e argumentos

Uma função executa uma tarefa. Os valores fornecidos à função são chamados argumentos.

Código 
notas <- c(7.5, 6.0, 8.2, 9.0, 5.8)
mean(notas)
[1] 7.3

Na expressão anterior:

  • mean é a função;
  • notas é o argumento;
  • o resultado é a média dos valores.

Outras funções básicas:

Código 
length(notas)
[1] 5
Código 
min(notas)
[1] 5.8
Código 
max(notas)
[1] 9
Código 
sum(notas)
[1] 36.5
Código 
sort(notas)
[1] 5.8 6.0 7.5 8.2 9.0
Leia o código como uma frase

mean(notas) pode ser lido como “calcule a média de notas”. Essa prática ajuda a compreender códigos novos.

2.8 Obtendo ajuda

O R possui documentação integrada.

Código 
?mean
help(mean)
help("mean")

Para pesquisar uma palavra na documentação:

Código 
help.search("median")

Para visualizar exemplos de uso:

Código 
example(mean)

Ao consultar a ajuda, procure:

  • Usage: forma de utilização;
  • Arguments: significado dos argumentos;
  • Value: objeto retornado;
  • Examples: exemplos executáveis.

2.9 Pacotes

Pacotes ampliam as funcionalidades do R.

2.9.1 Instalação

A instalação é feita normalmente uma única vez em cada computador.

Código 
install.packages(c(
  "tidyverse",
  "readxl",
  "writexl",
  "janitor"
))

2.9.2 Carregamento

O carregamento deve ser feito em cada nova sessão.

Código 
library(tidyverse)
library(readxl)
library(janitor)
Instalar e carregar são ações diferentes

install.packages() obtém o pacote e o instala no computador. library() disponibiliza suas funções na sessão atual.

2.12 Casos, variáveis e valores

Considere o banco estudantes:

Elemento Exemplo
Caso ou unidade observacional Um estudante
Variável idade
Valor observado 18 anos para Ana

Uma coluna não deve misturar significados

Uma coluna chamada resultado não deve conter, em algumas linhas, notas e, em outras, palavras como “aprovado”. Cada variável precisa ter um significado consistente.

2.13 Classificando as variáveis do banco

Variável Classificação sugerida
id Identificador; não deve ser resumido como quantidade
nome Texto identificador
turno Qualitativa nominal
idade Quantitativa; o tratamento depende da forma de registro
meio_transporte Qualitativa nominal
tempo_deslocamento_min Quantitativa contínua, embora registrada em minutos inteiros
horas_estudo_semana Quantitativa, conforme a precisão do registro
nivel_satisfacao Qualitativa ordinal

A classificação estatística e o tipo computacional não são exatamente a mesma coisa. Uma variável ordinal pode ser armazenada como texto, mas deve ter sua ordem explicitada quando necessário.

Código 
estudantes <- estudantes |>
  mutate(
    nivel_satisfacao = factor(
      nivel_satisfacao,
      levels = c(
        "Muito insatisfeito",
        "Insatisfeito",
        "Neutro",
        "Satisfeito",
        "Muito satisfeito"
      ),
      ordered = TRUE
    )
  )

class(estudantes$nivel_satisfacao)
[1] "ordered" "factor"

2.18 Princípios para organizar dados em planilhas

Uma planilha destinada à análise deve seguir, sempre que possível, estes princípios:

  1. uma linha por unidade observacional;
  2. uma coluna por variável;
  3. uma célula por valor;
  4. uma tabela por aba;
  5. nomes claros para as colunas;
  6. códigos explicados em um dicionário;
  7. valores ausentes representados de modo consistente;
  8. unidades de medida informadas;
  9. ausência de células mescladas dentro da tabela;
  10. ausência de subtotais misturados às observações.

2.18.1 Exemplo inadequado

Nome Informações
Ana 18 anos; noturno; ônibus
Bruno 20 anos; matutino; carro

Vários valores foram reunidos em uma única coluna.

2.18.2 Exemplo adequado

nome idade turno transporte
Ana 18 Noturno Ônibus
Bruno 20 Matutino Carro
Cor não deve ser o único registro

Não use apenas a cor da célula para indicar aprovação, ausência ou grupo. Essas informações devem estar registradas em uma variável explícita.

2.19 Valores ausentes em planilhas

Evite misturar diferentes códigos sem documentação:

  • célula vazia;
  • -;
  • 99;
  • 999;
  • Não se aplica;
  • Sem informação;
  • Não respondeu.

Esses estados podem ter significados diferentes. Um valor ausente deve ser identificado e, quando necessário, acompanhado do motivo da ausência.

No R, o valor ausente é representado por NA.

Código 
idades_com_ausencia <- c(18, 20, NA, 23)
idades_com_ausencia
[1] 18 20 NA 23
Código 
mean(idades_com_ausencia)
[1] NA

A função informa NA porque existe um valor ausente.

Código 
mean(idades_com_ausencia, na.rm = TRUE)
[1] 20.33333
Remover ausências não resolve automaticamente o problema

O argumento na.rm = TRUE exclui valores ausentes do cálculo, mas não explica por que eles estão ausentes nem se essa exclusão pode distorcer a análise.

2.20 Utilizando a internet de forma responsável

A internet pode ser utilizada para:

  • localizar bancos de dados;
  • consultar documentação de funções;
  • encontrar livros, artigos e relatórios;
  • verificar definições;
  • consultar fóruns técnicos;
  • obter exemplos de código.

Entretanto, nem toda informação disponível é confiável.

2.20.1 Checklist para avaliar uma fonte

Pergunte:

  1. Quem produziu a informação?
  2. A instituição ou o autor está identificado?
  3. A data de publicação está disponível?
  4. A metodologia foi explicada?
  5. A fonte original dos dados foi indicada?
  6. O conteúdo pode ser conferido em outra fonte?
  7. O material distingue opinião, propaganda e evidência?
  8. Os dados correspondem ao período e à população de interesse?

2.20.2 Estratégias de pesquisa

  • use aspas para procurar uma expressão exata;
  • acrescente o nome da instituição responsável;
  • utilize termos técnicos em português e inglês;
  • procure a documentação oficial de pacotes;
  • registre a página, o título, a instituição e a data de acesso;
  • prefira o dado original a reproduções sem fonte.

2.20.3 Sobre códigos encontrados na internet

Antes de utilizar um código:

  • leia cada comando;
  • verifique os nomes das funções;
  • execute por partes;
  • teste com um exemplo pequeno;
  • consulte a documentação;
  • confirme se o resultado possui interpretação;
  • registre adaptações realizadas.
Copiar não é reproduzir

Uma análise é reprodutível quando outra pessoa consegue compreender os dados, executar os procedimentos e obter os resultados. Copiar um código sem compreender as etapas não garante reprodutibilidade.

2.21 Edição de texto com Quarto

O Quarto permite combinar:

  • texto;
  • títulos e listas;
  • equações;
  • tabelas;
  • gráficos;
  • referências;

  • resultados produzidos pelo R.

Essa integração reduz a necessidade de copiar e colar resultados manualmente.

2.28 Renderizando o documento

Para transformar o arquivo .qmd em um documento:

  1. salve o arquivo;
  2. clique em Render;
  3. acompanhe as mensagens no painel de execução;
  4. corrija eventuais erros;
  5. verifique o arquivo gerado.
Erros são parte do aprendizado

Leia a mensagem de erro, identifique em qual bloco ela ocorreu e verifique nomes de objetos, parênteses, aspas, vírgulas, pacotes e caminhos de arquivos.

Problema Verificação inicial
Objeto não encontrado O nome foi escrito corretamente? O bloco anterior foi executado?
Função não encontrada O pacote foi instalado e carregado?
Arquivo não encontrado O arquivo está na pasta indicada? O projeto está aberto?

2.32 Síntese do Capítulo 2

  1. R é a linguagem; RStudio é o ambiente de trabalho.
  2. Projetos e caminhos relativos tornam a análise mais organizada.
  3. Comandos importantes devem ser registrados em scripts ou documentos Quarto.
  4. Pacotes precisam ser instalados e carregados.
  5. Uma tabela de dados possui casos nas linhas e variáveis nas colunas.
  6. CSV e XLSX possuem características diferentes.
  7. Planilhas para análise devem evitar células mescladas, subtotais e códigos sem documentação.
  8. A internet deve ser utilizada com avaliação crítica das fontes.
  9. Quarto reúne texto, código e resultados em um documento reprodutível.
  10. A interpretação é responsabilidade do analista, não do software.
